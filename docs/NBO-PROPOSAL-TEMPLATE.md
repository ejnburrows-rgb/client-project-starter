# NBO Implementation Proposal Template

## Operating problem

Describe the specific workflow problem in plain business language. State what is being lost, delayed, repeated or hidden from management.

## Outcome

State the visible result the client should have when the work is complete.

## Scope

### Included
- Workflow / screens / automation being implemented
- Roles that will use it
- English / Spanish requirements
- Data or files being connected
- Reporting / Needs Attention rules
- Human approval points

### Not included
List adjacent work that is explicitly outside this implementation.

## Client-owned systems

Document the CRM, phone, email, calendar, file storage or other tools that remain in place. NBO should not force migration without a concrete reason.

## Controls

- What can run automatically
- What requires human approval
- What owner / manager / staff can see or change
- What is logged in activity history
- Backup / export requirements

## Acceptance criteria

Use observable checks only. Examples:
- New intake enters one queue.
- Every active work item has an owner and next action.
- Overdue items appear in Needs Attention.
- English and Spanish versions follow the same operating rules.
- Required files remain attached to the correct record.
- Owner view shows the agreed management summary.

## Handoff

Include the working system, operating instructions, backup/export method and the final verified acceptance checklist.
